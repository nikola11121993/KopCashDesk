# Учет доходов — проектное задание

Отдельная от C:\BOT настольная система для учёта и сверки кассовых и банковских операций. Платформа: C# / .NET 10 / WPF, Windows x64. Язык интерфейса: русский.

## Первая версия

- Пустая локальная база SQLite, организации, торговые точки, привязки ККТ и терминалов.
- Рабочий стол, справочники, операции, сверка, интеграции, настройки, журнал и справка.
- Контекстные меню, горячие клавиши, доступные подписи, подтверждение удаления, понятные сообщения об ошибках, резервные копии и восстановление.
- Независимые адаптеры Такском ОФД и Астрал ОФД; настройки нескольких подключений по организациям. Реальные методы включаются только после проверки официальных схем и получения разрешённого доступа.
- Банковские реестры через IMAP и импорт файлов. Сбер API для POS-реестров не заявлен как доступный; его замена — согласованная банком почтовая рассылка. Никакой автоматизации личного кабинета через обход авторизации.
- Секреты отдельно от базы и настроек, защита Windows DPAPI, отсутствие секретов в Git и диагностике.
- Исходные документы и происхождение каждой операции сохраняются. Повторная загрузка не удваивает суммы. Неизвестные поля и виды операций не угадываются.
- Сверка исключительно кассового безнала с банковским безналом за сопоставимый период. Отдельно показывать наличные, возвраты, коррекции, комиссии, неполные данные и расхождения. Никаких автоматических фискальных коррекций или возвратов.
- Общий формат внутренних операций, версии схемы БД, модульные тесты, Windows CI и собираемый self-contained x64 пакет.

## Этапы

1. Пустая рабочая оболочка, справочники, защищённые настройки, тесты и CI.
2. Импорт реальных файлов и почтовый канал; проверка образцов банка.
3. Адаптеры ОФД на основе предоставленной документации и тестовых учётных данных, без публикации секретов.
4. Сверка, контроль полноты, отчёты, печать и удобные сценарии исправления сопоставлений.
5. Установщик, обновление с резервной копией и приёмочные тесты на Windows.

## Правила разработки

Каждое изменение проходит сборку и тесты. Наличие исходного кода не означает, что готов установщик или проверен реальный API. Старую программу, её файлы и базы не изменять. Не переносить реальные данные или реквизиты пользователя в репозиторий. Не включать неизвестные банковские/ОФД endpoint-ы и не объявлять заглушки работающими интеграциями.
