# ККТ, торговые точки и история

Физическая точка — адрес работы. Название ККТ не создаёт новую торговую точку.
В разделе «ККТ / Кассы» можно назначить точку и период, посмотреть архив изменений и непривязанные наблюдения.
При переезде необходимо указать дату начала; предыдущие даты остаются на старой точке. Конец периода включителен.
Для исправления ошибочной привязки за всё время есть отдельная явная отметка в форме.

Пример: две ККТ на АТИ с безналом 3457 и 100 дают 3557. Подтверждение одной смены из Frontol
не прибавляется к той же смене Taxcom. Сопоставление требует совпадения организации, точки, даты,
всех трёх сумм и времени в пределах пяти минут. Разные известные ФН не сопоставляются.
Конфликт сумм блокирует автоматический кассовый итог этого дня и его использование в FIFO.
Самостоятельные смены разных источников складываются; источник больше не выбирается один на всю точку за день.

Двойной щелчок по дню открывает расшифровку по ККТ, сменам и исходным операциям.
Ручное изменение сумм остаётся в контекстном меню. Непривязанная ККТ сохраняет исходные суммы,
но они не входят в итоги какой-либо физической точки до назначения.

## Миграция 3 → 4

Перед миграцией существующей схемы создаётся SQLite backup в каталоге Backups рядом с базой.
Миграция выполняется транзакционно, проверяет внешние ключи и сохраняет идентификаторы всех исходных записей.
`register_bindings` расширена полями заводского номера, названия, времени изменения и архивного состояния.
Уникальность только по ФН заменена поддержкой периодов. `location_id` допускает NULL для непривязанных ККТ/смен.
Метаданные ККТ сохранены также у исходных смен и фискальных операций.

Ручная привязка защищена приоритетом Manual и блокировкой. Изменение периода архивирует прежние записи,
сохраняет остатки интервалов и записывает старое/новое значения в audit. Импорт выбирает привязку по дате
наблюдения: закреплённая ручная, заводской номер, ФН, РНМ, явное правило, однозначная существующая
точка из поля отчёта. Неоднозначность и пробел в известной истории требуют ручного назначения.

Псевдо-точка автоматически объединяется только по явному правилу при однозначной целевой точке,
наличии привязок и отсутствии банковской истории, терминалов и ручных/закреплённых данных.
Прочие случаи попадают в список проверки. Старое исправление V051 больше не удаляет исходные смены/операции.

## Переезды и УБРиР

«Белокаменный кафе» → «Ленинградская 1» → последующие адреса — история переезда ККТ,
а не повод объединять все адреса. Исторический отчёт закрытого УБРиР продолжает участвовать в цифрах своего периода.
Правка ККТ не переносит банковские операции и не удаляет закрытые банковские источники.
Точные даты переездов должны подтверждаться исходными данными или задаваться пользователем.
Ранее выполненное ошибочное объединение не обращается автоматически: без дат и исходной принадлежности
записей такое восстановление было бы угадыванием. В интерфейсе появляется предупреждение для проверки.

## Проверка

Windows CI выполняет restore, build, весь набор xUnit tests и упаковку Windows x64.
Новые тесты покрывают независимые ККТ, исторические периоды, неизвестные ККТ, ручной приоритет,
смену ФН, РНМ, повторный импорт, FIFO, конфликт источников, мягкое объединение,
сохранение УБРиР и миграцию заполненной базы v3 с существующими ссылками.
